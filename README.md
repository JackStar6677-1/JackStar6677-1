I build and operate systems that have to survive contact with real users: Minecraft infrastructure, Java plugins, web applications, Linux services, school tooling, booking systems, and the automation around them.

My main project is **DrakesCraft**, a persistent Java and Bedrock server on Purpur 1.21.11. I lead its architecture, development, configuration, visual direction, deployments, incident response, and long-term maintenance.

## Current work

- **Minecraft engineering:** Java 21 plugins, Paper/Purpur APIs, Geyser/Floodgate, Slimefun compatibility, economy, inventories, world management, and live migration safety.
- **Original gameplay systems:** Odysseia, DiosesDrakes, ArcanaDrakes, DrakesBosses, dynamic markets, banking, protected graves, ranks, kits, and multimodal progression.
- **Compatibility maintenance:** restoring abandoned or outdated addons for Minecraft 1.21.11 while preserving IDs, recipes, machines, and player data.
- **Web and infrastructure:** Node.js, PHP, Docker, Cloudflare Tunnel, Linux operations, monitoring, backups, and deployment automation.
- **Education technology:** calendars, institutional sites, classroom tooling, workstation administration, and technical documentation.
- **Systems research:** Rust and Java native interop, persistence experiments, and performance work validated behind production-safe boundaries.

## How I work

- Stability and player data take priority over speculative performance gains.
- Production changes need a backup, a rollback path, and runtime evidence.
- Configuration should carry operational policy; code should carry invariants.
- Large systems stay understandable through explicit ownership boundaries and documented handoffs.
- Research is welcome, but experimental code is labeled honestly until it earns production status.
