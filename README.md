## What I operate today

### DrakesCraft

A persistent Java and Bedrock network built around Purpur 1.21.11 and a heavily maintained Slimefun ecosystem. I lead its architecture, development, visual direction, deployments, incident response and long-term operation.

- More than isolated plugins: a connected gameplay platform with multiple modalities, economies, progression systems and shared infrastructure.
- Java 21 maintenance and modernization for abandoned or incompatible projects without breaking item IDs, recipes, machines or player data.
- Transaction-safe inventories, modality boundaries, rollback paths, protected effects and production-aware deployment workflows.
- Original systems including **Odysseia, DiosesDrakes, ArcanaDrakes, DrakesBosses, DrakesNanotech**, dynamic markets, banking, ranks, cosmetics and world operations.

### Autonomous AI & Infrastructure Operations

- **[SAORI](https://github.com/JackStar6677-1/saori)** (*Server Autonomous Orchestrator for Resilient Infrastructure*): Autonomous tri-agent SRE operating system coordinating **Claude Code, OpenAI Codex, and Google Antigravity** over a single transactional SQLite WAL queue.
- Self-healing runtime: automated log ingestion, signature deduplication, live Maven patching (`mvn test package`), SHA-256 integrity checks, and zero-downtime safe staging (10/10 batch gate).
- Fine-grained concurrency leases preventing collisions across log observation, git repositories, panel API deployments and server reboots.
- Anti-prompt-injection zero-trust guardrails sanitizing untrusted player chat, Discord, books, and lore.
- Linux services, Docker workloads, Pterodactyl operations, Cloudflare, remote mounts, observability and recovery tooling.

### Education technology

I also build and maintain practical systems for school environments: workstation administration, laboratory tooling, Veyon automation, institutional sites, booking workflows, credentials and technical documentation that non-developers can actually use.

## How I engineer

```text
observe → correlate evidence → reproduce → protect data → patch → verify → stage → deploy → watch
```

- Player and user data outrank speculative performance gains.
- A production change needs evidence, a precise backup and a believable rollback path.
- Configuration carries policy; code carries invariants.
- Compatibility work preserves identities and data before adding features.
- Experimental systems stay labeled honestly until runtime evidence promotes them.
- Automation should reduce repetitive approval, never reduce accountability.
